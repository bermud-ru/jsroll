Локальные данные — dataObject() + crud()

dataObject() — фабрика, которая создаёт «локальный сервер»: функцию с сигнатурой, ожидаемой crud (той же, что обычно занимает настоящий xhr), но вместо сети работающую прямо с обычным JS-массивом в памяти. Пригодится для офлайн-заглушек, тестов UI без бэкенда или переключаемого источника данных («пока сервера нет — работаем локально, потом просто подменяем api на реальный xhr»).

new crud(dataObject(), meta) даёт тот же интерфейс (.data, .item(), .get/.post/.put/.del()), которым в остальных примерах пользуется xhr — здесь вместо реального запроса на сервер каждая операция читает/пишет обычный массив в памяти.
Пользователи (локально, в памяти)
IDИмяEmail
 
var api = dataObject();                                   // локальный "сервер" в памяти
var users = new crud(api, { id: null, name: '', email: '' }); // meta — шаблон пустой записи
users.data = [ { id: 1, name: 'Иван', email: 'ivan@example.com' }, … ];

// дальше — тот же интерфейс, что и с настоящим xhr-бэкендом:
users.get(null, { crud: users.data, after: function () { render(users.data); } });
users.post({ name: 'Мария', email: '...' }, { crud: users.data, primaryKey: 'id', after: render });
users.put({ name: 'Новое имя' }, { crud: users.data, index: 0, after: render });
Журнал событий
    Особенность, обнаруженная при проверке этого примера: crud.prototype.del() подставляет во внутренний вызов method: 'DELETE' (полное слово, как настоящий HTTP-метод), а dataObject() внутри себя сравнивает opt.method.toLowerCase() именно с коротким case 'del': — 'DELETE'.toLowerCase() даёт 'delete', что ни с одним case не совпадает, и удаление молча ничего не делает (остальные операции — 'post', 'put', 'get' — совпадают корректно, ломается только удаление). Рабочий обходной путь (используется в этом примере) — вызывать функцию, которую возвращает dataObject(), напрямую, минуя users.del(), и явно передать короткую форму метода: api({ method: 'del', crud: users.data, index: i, after: render }).
