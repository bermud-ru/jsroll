jsroll ← ко всем примерам

Web SQL — webSQL / webSQLmodel

Тот же набор из пяти сценариев, что и в примере IndexedDB (инициализация → создание таблицы → заполнение данными → просмотр всех таблиц → запрос с фильтром), но через второй офлайн-модуль jsroll — webSQL (низкоуровневая обёртка над openDatabase() в jsroll.js) и webSQLmodel (обёртка «одна таблица + DDL + синхронизация с сервером» в jsroll.dao.js).

Web SQL полностью удалён из всех современных браузеров. Chrome/Edge — начиная с версии 124 (апрель 2024), Safari — ещё в 2019, Firefox эту технологию не поддерживал никогда. Поэтому кнопки ниже, скорее всего, не заработают в вашем браузере — страница сама это определит ('openDatabase' in window) и заблокирует форму, если API недоступен. Пример оставлен как справочный по функционалу jsroll.js/jsroll.dao.js для случаев работы со старым кодом на legacy-платформах (встраиваемые WebView, Cordova/Electron со старым Chromium и т.п.), где openDatabase ещё может присутствовать — актуальный офлайн-аналог для новых браузеров — IndexedDB.
1. Инициализация — new webSQL(opt)

Открывает (или создаёт) базу через нативный openDatabase().

var sql = new webSQL({
    name: 'medicallabsDemo', version: '1.0',
    displayName: 'medicallabsDemo', estimatedSize: 500000
});
// … webSQLmodel(...) + .init() для каждой таблицы, см. блок 2 …
2. Создание таблицы — webSQLmodel(sql, opt) + model.init()

webSQLmodel (из jsroll.dao.js) — обёртка «таблица + DDL»: хранит имя таблицы, первичный ключ и SQL создания, init() выполняет DDL (CREATE TABLE IF NOT EXISTS …).

Ожидание подключения (блок 1)… 
var analysesModel = new webSQLmodel(sql, {
    modelName: 'Analyses', tableName: 'analyses', primaryKey: 'id',
    DDL: 'CREATE TABLE IF NOT EXISTS analyses ' +
         '(id INTEGER PRIMARY KEY AUTOINCREMENT, code TEXT, name TEXT, category TEXT, price INTEGER)'
});
// init(query, ver) не принимает callback — переопределяем done/fail САМОЙ модели:
analysesModel.done = function () { /* DDL выполнен */ };
analysesModel.init();
// patientsModel — аналогично, DDL для таблицы patients(id, name, phone)
3. Заполнение таблицы данными — sql.insert(table, rows, done, fail, webSQL.BULK)

Массовая вставка — CRUD для конкретных строк живёт в самом webSQL (не в webSQLmodel: та отвечает за DDL и постраничную синхронизацию с сервером через populate()/unload(), см. примечание внизу страницы). 

sql.insert('analyses', [
    {code:'OAK', name:'Общий анализ крови', category:'Кровь', price:450},
    {code:'BIOCH', name:'Биохимия крови', category:'Кровь', price:1200},
    // …
], function (tx, rs) { /* готово */ }, function (tx, err) { /* ошибка */ }, webSQL.BULK);
4. Демонстрация всех таблиц — sql.stmt('SELECT * FROM …')

У webSQL, в отличие от IDB.models, нет общего реестра созданных таблиц — какие таблицы есть, приложение отслеживает само (здесь — объект models), либо смотрит sql.info (SELECT * FROM sqlite_master …, лог в консоль). 

Object.keys(models).forEach(function (name) {
    sql.stmt('SELECT * FROM ' + models[name].tableName, [], function (tx, rs) {
        for (var i = 0; i < rs.rows.length; i++) { /* rs.rows.item(i) — очередная строка */ }
    });
});
5. Запрос с фильтром — sql.filter(query, params, done, fail)

Именованные параметры :name в SQL — значения подставляются через QueryParam() (с автоматическим экранированием строк). 

sql.filter('SELECT * FROM analyses WHERE category = :category', { category: 'Кровь' },
    function (tx, rs) { /* rs.rows — только строки с category = 'Кровь' */ },
    function (tx, err) { /* ошибка */ }
);
Журнал событий
    Особенности, обнаруженные при проверке этого примера:
    • webSQLmodel.init(query, ver) не принимает callback завершения — чтобы узнать, что DDL выполнен, нужно переопределить model.done/model.fail (это методы прототипа с поведением по умолчанию «просто в консоль») ДО вызова init(), как сделано в этом примере.
    • sql.opt по умолчанию — QueryParam.STRNULL | QueryParam.INTQOUTED, БЕЗ QueryParam.QOUTED. Из-за этого именованные параметры в sql.filter() подставляются в SQL как значения без кавычек — строка category = Кровь вместо category = 'Кровь' (SQLite трактует её как обращение к несуществующему столбцу и возвращает ошибку). Здесь это исправлено один раз при инициализации: sql.opt |= QueryParam.QOUTED;.
    О webSQLmodel.populate()/.unload(): помимо init() (DDL), у webSQLmodel есть методы постраничной синхронизации с сервером — populate(opt) скачивает данные с opt.url и вставляет их локально (BULK|UPSERT), а unload(query, countQuery, opt) отправляет локальные данные на сервер порциями. Оба метода по своей сути требуют настоящего backend'а (обращаются через xhr()), поэтому в этом самодостаточном примере без сервера не показаны — здесь используются более простые, не привязанные к сети операции: init(), sql.insert(), sql.stmt(), sql.filter().
