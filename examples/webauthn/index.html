Биометрическая аутентификация — WebAuthn

Вход по отпечатку пальца / Face ID / Windows Hello вместо пароля, через новый модуль jsroll.auth.js — обёртку над браузерным Web Authentication API в стиле остального jsroll: класс с шиной событий как у Application (addEventListener/dispatchEvent), {done,fail}-колбэки как у xhr().

Это самодостаточная демонстрация без сервера — не пример готовой к продакшену защиты. WebAuthn существует ради того, чтобы challenge генерировался и подпись ответа проверялась на СЕРВЕРЕ. Здесь challenge генерируется прямо в браузере (crypto.getRandomValues), а «своим» пользователь считается по совпадению credential id, сохранённого в localStorage этого же браузера — то есть страница верит сама себе. В реальном приложении opt.challenge в register()/authenticate() нужно получать с сервера, а результат — отправлять на сервер для криптографической проверки (см. пояснение в конце страницы и комментарии в самом jsroll.auth.js).
Проверка поддержки браузером…
Если браузер отвечает «The requested RPID did not match the origin or related origins»: это не баг примера, а защита самого WebAuthn — она сработает, если страница открыта не как обычная вкладка браузера на своём собственном адресе (например, через встроенный предпросмотр/прокси/iframe, которые подменяют или скрывают реальный адрес страницы). Откройте эту страницу напрямую в отдельной вкладке браузера (после скачивания — через локальный сервер, например python3 -m http.server из корня проекта, или через любой другой статический хостинг) — и ошибка исчезнет сама, без каких-либо действий с кодом.
Регистрация — webauthn.register(user, opt)

Привязывает биометрический ключ этого устройства к имени пользователя.

webauthn.register({ id: 'andrey', name: 'andrey', displayName: 'Андрей' }, {
    done: function (credentialInfo) { /* ключ создан и сохранён локально */ },
    fail: function (err) { /* пользователь отменил / ошибка */ }
});
Вход — webauthn.authenticate(opt)

Подтверждение личности той же биометрией, без пароля.

// с конкретным пользователем — предложит только его ключи
webauthn.authenticate({ userId: 'andrey', done: function (r) { /* r.userId, r.credentialId */ } });
// без userId — браузер сам покажет выбор из сохранённых на устройстве ключей
webauthn.authenticate({ done: function (r) { /* r.userId определился по credential id */ } });
Зарегистрированные на этом устройстве — webauthn.users()

Локальный реестр (localStorage) — какие имена пользователей привязаны к ключам этого браузера/устройства.

Пока никто не зарегистрирован.

Журнал событий
    Как встроить по-настоящему, с сервером:
    1. Сервер генерирует случайный challenge и отдаёт его вместе с параметрами регистрации/входа (например, через xhr({url:'/webauthn/register-options'})) — передайте его как opt.challenge в register()/authenticate() вместо значения по умолчанию.
    2. Результат register()/authenticate() (объект credential/ assertion из колбэка done) целиком уходит на сервер (тем же xhr(), бинарные поля — через bufferToBase64url() из этого модуля) — сервер проверяет подпись и решает, пускать пользователя или нет. Локальное совпадение credential id в этом примере — не замена этой проверке, а просто способ показать демо без бэкенда.
    3. Идентификатор пользователя (user.id) в проде — непрозрачный случайный идентификатор с сервера, а не имя пользователя напрямую (здесь он используется в открытую только ради простоты демонстрации).
