Роутер urn

Ядро (src/jsroll.js) экспортирует глобальный объект window.urn (не window.router — учтите это при переносе кода из старой документации). Методы: urn.add(шаблон, обработчик) — зарегистрировать маршрут, urn.lsn() — начать слежение за изменением адреса (опрос раз в 30 мс), urn.set(путь) — программно перейти по маршруту, urn.chk() — вручную проверить текущий адрес против зарегистрированных маршрутов.

Если браузер поддерживает history.pushState (сейчас — всегда), urn использует его: адресная строка меняется по-настоящему, без перезагрузки страницы.
Ограничение конструкции: сама функция-конструктор urn(root) нигде не экспортируется наружу — доступен только один готовый глобальный экземпляр window.urn, созданный внутри библиотеки с root = '/' (g.urn = urn('/')). Поэтому urn.set('users/42') переходит на абсолютный адрес /users/42 от корня домена, а не на путь относительно текущей папки. Это нормально для приложения, которое (как dashboard-web) целиком отдаётся с корня домена одной точкой входа — но делает urn неудобным для демо-страницы, лежащей во вложенной папке examples/router/: после перехода обновление страницы, скорее всего, вернёт 404, если сервер не отдаёт index.html на любой путь.
