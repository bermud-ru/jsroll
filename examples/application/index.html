Application — жизненный цикл SPA-приложения

Пример по мотивам загруженного фрагмента common.app.js: та же связка «вкладки синхронизированы с ?tab= в адресной строке через urn», dropdown-меню пользователя, кастомные события app.login/app.logout и куки-сессия. Отличие — здесь нет настоящего бэкенда: вход эмулируется прямо в браузере (в реальном приложении на месте app.setCookie(...) в обработчике кнопки «Войти» был бы xhr({url:'/login', ...}), как в исходном файле).

Что здесь происходит по шагам: 1) при загрузке страницы создаётся window.app = new Application('1.0.0') — статус ниже; 2) пока нет сессии — показан экран входа; 3) после входа — панель с вкладками, переключение которых хранится в адресной строке через urn (тот же механизм, что и в tabulator() из приложенного common.app.js).

Активная вкладка хранится в адресной строке (?tab=1) через urn.set() — можно обновить страницу или скопировать ссылку, вкладка не потеряется.

Включите и попробуйте закрыть или обновить вкладку браузера.

    Что здесь показано
    • window.app = new Application(version) — создание единственного экземпляра приложения.
    • app.onready(fn) — код выполняется после DOMContentLoaded.
    • app.addEventListener/dispatchEvent + ce (CustomEvent) — вход/выход как в common.app.js.
    • app.setCookie/getCookie/clearCookie — сессия пользователя.
    • app.changeVersion(fn) — колбэк на смену app.version.
    • app.confirmReload — встроенное подтверждение ухода со страницы.
    • urn.add(handler).chk().lsn() + location.params()/update() — вкладки, синхронные с URL.
    • dropdown-меню пользователя: ui.el('[ui="auth"]', …), css.tgl('show'), закрытие по blur.
